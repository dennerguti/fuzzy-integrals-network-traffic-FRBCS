# Fuzzy Integrals for Network Traffic Prediction

Python implementation of Choquet-based fuzzy integrals with the **Power Measure** applied to one-step-ahead forecasting of network traffic.

This repository contains the source code and the dataset used in the network-traffic experiments of the paper:

> **Evaluating the Power Measure with Choquet-Based Generalizations with Different Applications**

## Overview

Given the last `n` observations of a packet-count series (a sliding window), each operator aggregates the window into the forecast of the next value. The fuzzy measure is the Power Measure

$$m(A) = \left(\frac{|A|}{n}\right)^q, \qquad q > 0,$$

which reduces to the uniform (additive) measure when `q = 1`. The Poisson Moving Average (PMA) is used as the baseline.

| Code | Operator | Code | Operator |
|---:|---|---:|---|
| 0 | Choquet integral | 5 | C<sub>F1F2</sub>-integral (`CF1F2`) |
| 1 | C<sub>C</sub>-integral with min (`CC-min`) | 6 | d-C<sub>F</sub>-integral (`dCF`) |
| 2 | C<sub>T</sub>-integral (`CT`) | 7 | d-C<sub>C</sub>-integral (`dCC`) |
| 3 | C<sub>F</sub>-integral, averaging (`CF-AVG`) | 8 | d-X<sub>C</sub>-integral (`dXC`) |
| 4 | C<sub>F</sub>-integral, non-averaging (`CF-nonAVG`) | | |

### Using the library

```python
import sys; sys.path.insert(0, "src")
from fintraffic import load_series, forecast, choquet_integral

series = load_series("data/compilado.csv")
preds = forecast(series, window=5, method="CC-min", q=3.0, start=70)   # rounded forecasts
choquet_integral([0.2, 0.9, 0.5], "Choquet", q=1.0)                      # = mean = 0.5333
```

## Dataset

`data/compilado.csv` is a series of packet counts aggregated every 5 seconds, derived from the CIC-IDS2017 dataset. It has 29,405 observations and **no header row** (columns: `HH:MM:SS`, number of packets). The series is highly skewed (mean ≈ 1993, median 487), with bursts of up to 45,030 packets.

## Methodology

* **Forecast.** For each target `t`, the window `x[t-n], …, x[t-1]` is aggregated and the result, rounded to the nearest integer, is the forecast of `x[t]`. The error metric is the MAE in packets.
* **Normalization (Eq. 15).** Each window is divided by its maximum before aggregation, and the result is multiplied back by the same maximum.
* **Codomain.** For inputs in [0, 1], CF-nonAVG, CF1F2, dCF, dCC and dXC take values in [0, n]; their output is divided by `n` so that every operator returns a value in [0, 1]. The `min{1, ·}` cap of the original definitions is **not** applied, because with normalized windows it saturates almost every forecast at the window maximum. The capped variant can be reproduced with `AggregationConfig(normalize=True, rescale_by_n=False, cap_at_one=True)`.
* **Common test set.** All window sizes forecast from `t = 70` (the largest window), so every configuration is evaluated on the same targets.
* **Validation/test.** The evaluation period is split in half: the first half selects the window and `q`, and the second half reports the error.

## Main results

(window, q) selected on validation, MAE on test (`results/selection_validation_test.csv`):

| Operator | Window | q | MAE (validation) | MAE (test) |
|---|---:|---:|---:|---:|
| Choquet | 5 | 2.5 | 1126.67 | 849.49 |
| CT | 5 | 3.0 | 1153.73 | 875.11 |
| CC-min | 5 | 3.0 | 1164.27 | 879.75 |
| CF-AVG | 5 | 3.0 | 1191.90 | 905.94 |
| CF1F2 | 5 | 1.5 | 1506.61 | 1096.61 |
| CF-nonAVG | 5 | 0.8 | 1657.32 | 1229.81 |
| dCC | 5 | 1.25 | 1740.44 | 1253.29 |
| dXC | 5 | 0.9 | 1775.17 | 1281.07 |
| dCF | 5 | 0.2 | 1775.28 | 1282.00 |

On the test period, CC-min with the q selected on validation reduces the MAE of the PMA by 4.0% (window 40) to 22.8% (window 5). For six of the nine operators the best `q` is greater than 1 in most windows, i.e., the non-additive Power Measure outperforms the uniform measure.
